## Project Overview

This is an Infrastructure as Code project for deploying a Minecraft server on AWS with Discord bot control. The stack uses OpenTofu (Terraform-compatible) for infrastructure, Ansible for configuration management, and Python Lambda functions for a Discord bot.

## Common Commands

```bash
# Initial setup (interactive - creates credentials, tfvars, Python venv)
make init

# Full deployment pipeline (infrastructure + configuration, ~10 min)
make deploy

# Dry-run infrastructure changes
make plan

# Apply only infrastructure changes (no Ansible)
make apply

# Run Ansible playbooks only
make ansible-setup    # System setup (Docker, monitoring)
make ansible-deploy   # Deploy Minecraft server

# Sync Tofu outputs to Ansible inventory
make sync

# Build Lambda Layer ZIP
make build-layer

# Run Python tests
make test

# View infrastructure status
make status

# Connect to EC2 via SSM
make ssh

# View Minecraft server logs
make logs

# View Discord bot Lambda logs
make lambda-logs

# Register Discord slash commands
make discord-setup

# Destroy all AWS resources (prompts for confirmation)
make destroy
```

## Architecture

### Deployment Pipeline

`make deploy` runs these steps in sequence:
1. Verify secrets (`.secrets/credentials.yml`, `tofu/environments/prod.tfvars`)
2. Build Lambda layer ZIP (`discord-bot/dist/lambda_layer.zip`)
3. `tofu apply` — create/update AWS resources
4. `scripts/sync_infra.sh` — extract Tofu outputs → `ansible/inventory/host_vars/minecraft-server.yml`
5. Ansible setup playbook — install Docker, monitoring
6. Ansible deploy playbook — start Minecraft via Docker Compose

### Infrastructure (tofu/)

- **VPC**: 10.0.0.0/16 with a single public subnet (10.0.1.0/24)
- **EC2**: Amazon Linux 2023, t3.medium, 30GB gp3 EBS; accessible only via SSM (no SSH keys)
- **Security Groups**: Port 25565/TCP (Java), 19132/UDP (Geyser/Bedrock), 25575/TCP RCON (VPC-internal only)
- **Lambda (dual architecture)**:
  - `handler.py` — receives Discord webhooks, verifies signatures, dispatches async work (30s timeout)
  - `worker.py` — performs EC2 control and SSM commands, sends Discord webhook responses (300s timeout)
- **S3**: backup bucket (versioning, 30-day lifecycle) + SSM session logs bucket (1-day lifecycle)
- **CloudWatch**: Alarms, dashboard, metric filters for player join/leave events

### Discord Bot (discord-bot/)

- `src/handler.py` — Lambda entry point; signature verification via PyNaCl
- `src/worker.py` — async Lambda; handles `/server start|stop|status|backup|logs`
- `src/commands/server.py` — command implementations
- `src/utils/ec2.py` — EC2 start/stop/describe
- `src/utils/ssm.py` — run Ansible commands on EC2 via SSM Send-Command
- Dependencies packaged as a Lambda Layer (built via `scripts/build-lambda-layer.sh`)

### Ansible (ansible/)

- EC2 connection uses AWS SSM plugin (no SSH keys required)
- **Roles**: `common` (system packages), `docker` (Docker install), `monitoring` (CloudWatch agent), `minecraft` (server deployment)
- `minecraft` role tasks: `setup.yml` (Docker Compose), `backup.yml` (cron + S3), `auto-stop.yml` (cron every 5 min)
- Minecraft runs as `itzg/minecraft-server` Docker image with Geyser JAR for Bedrock client support

### Secrets & Configuration

- `.secrets/credentials.yml` — RCON password (gitignored, mode 600)
- `.secrets/discord.env` — Discord Application ID, Public Key, Bot Token (gitignored, mode 600)
- `tofu/environments/prod.tfvars` — production variables (generated by `make init`)
- All secrets are injected into Lambda environment variables via Tofu

### CI/CD (.github/workflows/)

- **ci.yml**: On push/PR — tofu fmt+validate, flake8+black, pytest, ansible-lint, gitleaks+tfsec
- **deploy.yml**: On push to main — build layer, `tofu apply`, register Discord commands
- **plan.yml**: On PR — `tofu plan` output posted as PR comment

## Key Implementation Details

- OpenTofu is used (not Terraform); commands use `tofu` not `terraform`
- Python is tested with pytest; run with `make test` (sets mock env vars automatically)
- Lambda layer uses `manylinux2014_x86_64` wheels for Linux compatibility
- EC2 auto-stop runs every 5 minutes via cron checking for inactive players
- Tofu backend uses S3 (configured in `tofu/main.tf`); local state is gitignored
- flake8 max line length is 120 chars; formatter is black
